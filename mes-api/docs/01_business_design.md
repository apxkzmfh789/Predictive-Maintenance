# 1단계 업무 설계 — 예지보전 경보·보전 작업지시

> 작성일: 2026-10-23 · 수정일: 2026-10-26 · 작성자: 이창우
> 대상: `mes-api` (Java 21 · Spring Boot · MyBatis · SQL Server)

## 1. 목적과 범위

- Python 예측 결과(설비별 30분 내 고장 확률)를 받아 **경보 → 보전 작업지시 → 조치 완료 → 이력·집계**로 이어지는 현장 업무를 처리
- 포함: 설비 기준정보, 예측 결과 적재, 경보 관리, 보전 작업지시, 상태 변경 이력, 집계
- 제외 (진행 상황 보고 결정): 로그인·권한, 웹 화면, Docker, 서버 배포, 설비 직접 연동(MQTT 등)

## 2. 업무 흐름

```
① 설비 기준정보 등록 (CNC-01 ~ 03)
② 예측 결과 적재: models/recent/test_predictions.csv + metrics.json(임계값)
   (CSV의 ts는 UTC → +9시간 해서 한국 시간으로 저장)
③ 경보 판정: 고장 확률 ≥ 경보 임계값이 연속 2분 → 경보 발생
   (같은 설비에 열린 경보가 있으면 새로 만들지 않고 갱신)
④ 작업자가 경보 확인
   ├─ 점검 필요 → ⑤ 보전 작업지시 생성
   └─ 헛경보    → 경보 종료 (사유: 오경보)
⑤ 작업지시: 대기 → 진행 → 완료 (담당자, 작업 유형, 결과 코드, 조치 내용 기록)
   진행 중에는 설비 상태 = 정비중
⑥ 작업지시 완료 → 연결된 경보 자동 종료 (사유: 조치 완료), 설비 상태 = 가동
⑦ 이력·집계 조회
```

## 3. 상태 정의

### 3.1 경보

| 상태 | 의미 | 다음 상태 |
|---|---|---|
| `OPEN` 발생 | 시스템이 감지, 아직 확인 전 | `ACK` |
| `ACK` 확인 | 작업자가 확인 | `CLOSED` |
| `CLOSED` 종료 | 처리 끝 | 없음 |

- 종료 사유 필수: `RESOLVED` 조치 완료 / `FALSE_ALARM` 오경보
- `OPEN` → `CLOSED` 직행 불가 (사람이 확인한 기록을 남기기 위함)

### 3.2 보전 작업지시

| 상태 | 의미 | 다음 상태 |
|---|---|---|
| `WAITING` 대기 | 생성됨, 작업 시작 전 | `IN_PROGRESS`, `CANCELED` |
| `IN_PROGRESS` 진행 | 작업 중, 시작 시각 기록 | `DONE` |
| `DONE` 완료 | 조치 끝, 완료 시각·결과 기록 | 없음 |
| `CANCELED` 취소 | 대기 상태에서만 가능 | 없음 |

- 작업 유형: `INSPECTION` 점검 / `REPAIR` 수리 / `REPLACE` 교체
- 결과 코드: `NO_ISSUE` 이상 없음 / `ADJUSTED` 조정 / `PART_REPLACED` 부품 교체 / `REPAIRED` 수리

### 3.3 설비

| 상태 | 의미 |
|---|---|
| `RUNNING` 가동 | 기본 상태 |
| `MAINTENANCE` 정비중 | 연결된 작업지시가 진행 중 |

## 4. 업무 규칙

| 번호 | 규칙 |
|---|---|
| R1 | 경보 임계값 기본값은 적재 시 `metrics.json`의 `threshold` 사용 |
| R1-1 | 설정값 `경보 임계값 재정의`가 있으면 그 값을 우선 사용 |
| R2 | 같은 설비·같은 데이터 시각의 예측은 한 번만 저장 (재적재 시 무시) |
| R3 | 같은 설비에 `OPEN`·`ACK` 경보가 있으면 새 경보를 만들지 않고 최고 확률·마지막 감지 시각·감지 횟수만 갱신 |
| R3-1 | 임계값 초과가 **연속 2분** 이어질 때만 경보 발생 (통신 공백 2분 초과 시 연속 횟수 초기화). 데이터 시각 기준 |
| R3-2 | 경보 종료 후 **30분** 동안 같은 설비 경보 재발생 금지. 데이터 시각 기준, 종료 시점에 그 설비의 마지막 데이터 시각부터 계산 |
| R4 | 작업지시는 `ACK` 경보에서만 생성, 경보 하나당 진행 중(`WAITING`·`IN_PROGRESS`) 작업지시는 1개 |
| R5 | 작업지시 완료 시 결과 코드와 조치 내용 필수, 완료 시각 기록, 연결 경보는 `CLOSED(RESOLVED)` |
| R5-1 | 작업 시작 시 설비 상태 `MAINTENANCE`, 완료·취소 시 `RUNNING` |
| R6 | 오경보 종료 시 메모 필수 |
| R7 | 모든 상태 변경은 이력에 기록 (대상, 이전 상태 → 이후 상태, 변경자, 시각, 메모) |
| R8 | 담당자·변경자는 이름 문자열로 저장 (로그인 없음) |
| R9 | 규칙에 어긋나는 요청은 거부하고 이유를 응답 |
| R10 | 상태 변경은 현재 상태를 조건으로 건 UPDATE로 처리, 바뀐 행이 0건이면 거부 (동시 처리 방지) |

### 설정값

| 이름 | 기본값 | 관련 규칙 |
|---|---|---|
| 경보 임계값 재정의 | 없음 (`metrics.json` 사용) | R1-1 |
| 발생 지연 연속 횟수 | 2 | R3-1 |
| 재발생 금지 시간 | 30분 | R3-2 |

### 집계 지표 정의

| 지표 | 계산 |
|---|---|
| 경보 수 | 기간 내 발생한 경보 건수 |
| 오경보율 | `FALSE_ALARM` 종료 경보 ÷ 종료된 경보 |
| 현장 확인 헛경보율 | 결과 `NO_ISSUE` 작업지시 ÷ 완료된 작업지시 |
| 평균 확인 시간 | 경보 생성 시각 → 확인 시각 |
| 평균 조치 시간 | 경보 확인 시각 → 작업 완료 시각 |
| 비가동 시간 | 작업지시 시작 → 완료 시간의 합 |

- 시간 지표는 **처리 시각**(시스템이 기록한 실제 시각) 기준

## 6. 설계 결정 기록

| 번호 | 결정 | 이유 |
|---|---|---|
| D1 | 열린 경보가 있으면 새로 만들지 않고 갱신 (R3) | 1분 단위 예측마다 경보가 쌓이는 경보 폭주 방지 |
| D2 | 작업지시는 작업자 확인 후 수동 생성 (R4) | 확률 모델은 헛경보가 많아 사람 판단을 거치는 것이 현실적 |
| D3 | 담당자는 이름 문자열 (R8) | 로그인을 범위에서 제외 |
| D4 | 발생 지연 2분 (R3-1) | 아래 7장 시뮬레이션: 임계값 초과 구간의 37%가 1분짜리 튐, 2분이면 1분 비용으로 제거, 3분 이상은 효과가 거의 없음 |
| D5 | 재발생 금지 30분 (R3-2) | 예측 범위(30분 내 고장)와 일치, 시뮬레이션상 경보 수를 실제로 통제하는 규칙 |
| D6 | 경보 임계값을 모델 임계값과 분리 가능하게 함 (R1-1) | 모델 임계값은 1분 단위 예측의 비용 최소점이라 경보 시스템의 최적값과 다름. 기본값은 모델과 일관성을 위해 `metrics.json` 유지 |
| D7 | "MTTR" 대신 평균 확인 시간·평균 조치 시간 사용 | MTTR은 실제 고장부터 복구까지의 지표인데, 이 시스템의 경보는 고장이 아니라 고장 예측 |
| D8 | 작업 결과를 코드로 받음 | `NO_ISSUE` 비율이 현장에서 확인된 헛경보율이 되어 임계값 재조정의 근거가 됨 (예측 ↔ 현장 피드백) |
| D9 | 설비 상태를 작업지시와 연동 (R5-1) | 현장이 가장 먼저 보는 정보, 비가동 시간 집계의 근거 |
| D10 | 조건부 UPDATE로 상태 변경 (R10) | 두 작업자가 같은 경보를 동시에 처리하는 경우 방지 |
| D11 | 모든 시각은 한국 시간(KST)으로 저장, CSV의 ts(UTC)는 적재 시 +9시간 | 한 공장 시스템이고 일별 집계와 현장 화면이 한국 시간 기준. 해외 공장이 붙으면 `DATETIMEOFFSET`으로 변경 필요 |
| D15 | 경보 판정 규칙(R3-1, R3-2)은 데이터 시각, 집계 지표는 처리 시각 기준 | 예측이 하루치 파일로 들어와 두 시각이 다름. 재발생 금지를 처리 시각으로 세면 과거 데이터에서는 경보가 다시 생기지 않음 |

- D12~D14, D16~D18은 테이블 구조 결정이라 `02_db_design.md`에 기록

## 8. 미결 사항

- 시연용 구간 적재: 하루치를 한 번에 적재하면 적재 중에는 확인·종료가 불가능해 설비당 경보가 1건으로 흡수됨 → 적재 API에 시간 구간(from/to)을 받는 방식 검토 (4단계)
- 등록되지 않은 설비 코드가 CSV에 있을 때 파일 전체 거부 또는 해당 행만 건너뛰기 (4단계)
